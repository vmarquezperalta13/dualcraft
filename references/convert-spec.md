# Neutral conversion spec (`.dualcraft/convert/`)

Platform-neutral description of the app, written by the **analyze** step from the source code and read by the **generate** step. It references the project's shared sources instead of copying them: entities → `.dualcraft/db/schema.dbml`, texts → `.dualcraft/i18n`, events → `.dualcraft/analytics/events.json`, look → design tokens.

## Files
```
.dualcraft/convert/
  inventory.json        generated by convert.mjs inventory (screens, features, touchpoints)
  status.json           progress per feature + backend decisions (convert.mjs init/set/backend)
  spec/app.json         app-level: navigation, auth, features
  spec/screens/<id>.json  one per screen
```

### Vocabulary
- Node `type`: `page` `header` `section` `text` `image` `icon` `stat` `list` `grid` `table` `card` `form` `field` `action` `tabs` `overlay` (dialog/sheet — platform decides) `empty` `banner` `custom` (with `description` when nothing fits).
- Values: `i18n:<key>` (text from the shared source), `data:<Entity>.<field>` (from the schema), `token:<name>` (design token), or a literal only for non-text values.
- `does`: `navigate:<screen>` · `back` · `mutate:<Entity>.<create|update|delete>` · `backend:<name>` (a server operation — see backend decisions) · `external:<url>` · `share` · `custom:<description>`.
- `rules`: business rules in plain language — each one becomes a test case on **both** platforms.

## status.json
```json
{
  "from": "web", "to": "mobile", "target": "apps/mobile", "createdTarget": true,
  "features": [ { "id": "matches", "screens": ["matches", "match-detail"], "state": "verified", "task": "T-031" } ],
  "backend": [ { "id": "api:/api/reserve", "kind": "route-handler", "used_by": ["match-detail"], "options": ["expose-api", "move-to-functions"], "recommended": "move-to-functions", "decision": "move-to-functions", "why": "…" } ]
}
```
Feature states: `pending` → `spec` → `adapted` → `generated` → `verified` → `done` (or `skipped`).
Backend decisions: `pending` · `shared` (both clients use it as is) · `expose-api` (make it callable from the other platform with auth) · `move-to-functions` · `duplicate` (non-sensitive client logic, with shared test cases) · `alternative` (a different platform service, e.g. IAP ⇄ Stripe) · `skip` (feature not offered on the target).
